# 参照画像の安全検知設計

最終確認日: 2026-08-01

## 1. 目的

Pina Studioで参照画像を使った動画生成を一般ユーザーへ再開する前に、実在人物へのなりすまし、未成年・児童画像、既知CSAM（児童性的虐待コンテンツ）を生成開始前に検知し、安全に停止するための設計を定める。

この文書は調査・設計段階の方針であり、専用検知の実装完了や一般ユーザー向け再開を意味しない。

## 2. 現在の状態

- 一般ユーザーの参照画像付き動画生成は停止中である。
- `api/seedance-start-priced.js`は、参照画像を含むリクエストを、タスク作成、クレジット控除、DB書き込み、OpenRouter呼び出しより前にHTTP 503で停止する。
- 環境変数`TEST_BYPASS_USER_ID`と一致する確認済みユーザー1名のみ例外とする。
- 例外ユーザーも既存のOpenAI Moderationを省略しない。
- テキストのみの動画生成は既存フローを維持する。

専用検知が本番で安全に動作することを確認するまで、この停止を解除しない。

## 3. 現行モデレーションで確認できる範囲

`api/_lib/openai-moderation.js`は、文章と各参照画像を別々にOpenAI Moderationへ送信し、有害カテゴリーを確認する。

ただし、現行処理だけでは次を保証できない。

- 写っている人物が実在人物か、架空人物か
- 有名人・著名人本人であるか
- 顔から推定した年齢が18歳以上であるか
- 既知CSAMのハッシュと一致するか
- 未登録・新規のCSAMであるか
- 実在人物から画像利用の同意を得ているか

したがって、OpenAI Moderation単独を理由に参照画像生成を再開しない。

## 4. 絶対に緩和しない基準

次のいずれかに該当する、または安全に否定できない場合は生成を許可しない。

- 未成年に見える人物・キャラクターの性的描写
- 児童への性的搾取につながる画像
- 既知CSAMとの一致
- 実在人物へのなりすまし
- 有名人・著名人の無断利用
- 非同意の性的画像
- 年齢判定不能または18歳未満の可能性
- 専用検知サービスの障害・タイムアウト・形式不正

一般的な非グラフィックのアニメ戦闘、変身、魔法、露出の少ない普段着等は、上記の具体的な危険根拠がない限り過剰に拒否しない。ただし、人物の年齢や実在性を安全に確認できない参照画像は、一般的な表現であっても参照画像生成では停止する。

## 5. 候補サービスの役割

### 5-1. Thorn Safer Match

用途:

- 既知CSAMの暗号学的ハッシュ照合
- 改変された既知画像に対する知覚ハッシュ照合

確認できたこと:

- ThornがホストするAPI形式が提供されている。
- 信頼できる情報源から集約された既知CSAMハッシュとの照合を行う。
- AWS Marketplace経由の提供も案内されている。

限界:

- Safer Matchだけでは、既知データベースにない新規CSAMを完全には検出できない。
- 契約条件、料金、リクエスト画像の保持、利用可能地域、日本の個人事業者が利用できるかは契約前に確認が必要である。

公式情報:

- https://safer.io/resources/introducing-safer-essential-api-based-csam-detection/
- https://safer.io/solutions/

### 5-2. Thorn Safer Predict

用途:

- 既知ハッシュに一致しない可能性がある画像・動画を、予測分類で検出する補助候補

注意:

- 誤判定があり得るため、単独で自動通報・自動削除を行わない。
- 提供形態、料金、利用審査、画像保持、API利用可否は要問い合わせとする。
- 導入可能な場合も、Safer Matchと役割を分離して扱う。

公式情報:

- https://safer.io/solutions/

### 5-3. Microsoft PhotoDNA

用途:

- 既知CSAMとのハッシュ照合候補

確認できたこと:

- PhotoDNA Cloud Serviceの利用はMicrosoftの適格性審査と裁量に基づく。
- 利用者側の法的な報告義務を代替しない。

限界:

- 利用申請が承認される保証はない。
- 料金、画像保持、利用地域、個人事業者としての適格性は申請前後に確認が必要である。

公式情報:

- https://www.microsoft.com/en-us/photodna/TermsofUse

### 5-4. Amazon Rekognition DetectFaces

用途:

- 顔の有無の検出
- 顔ごとの年齢範囲を含む属性取得の候補

確認できたこと:

- `DetectFaces`はステートレスAPIであり、このAPI操作自体はデータを永続化しないとAWSが説明している。
- 顔属性は推定値であり、正確な年齢確認ではない。

重要なデータ取扱い:

- AWSの説明では、Rekognition APIへ渡した画像は、AIサービスのオプトアウトを行わない場合、サービス改善のため保存・利用される可能性がある。
- 保存される画像は暗号化されると説明されている。
- 導入する場合は、AWS AIサービスのデータ利用オプトアウトを設定し、その設定を確認・記録する。

限界:

- 年齢範囲が18歳をまたぐ場合、成人とは判断できない。
- 顔が小さい、横向き、隠れている、イラスト調等の場合は判定不能となる可能性がある。
- 年齢推定だけでCSAMではないと判断しない。

公式情報:

- https://docs.aws.amazon.com/rekognition/latest/APIReference/API_DetectFaces.html
- https://docs.aws.amazon.com/rekognition/latest/dg/security-data-encryption.html

### 5-5. Amazon Rekognition RecognizeCelebrities

用途:

- AWSが認識対象としている有名人・著名人との一致確認候補

確認できたこと:

- 画像内の大きい顔を最大64件まで確認する。
- 認識した有名人について名前、ID、一致度等を返す。
- AWSは、どの画像で有名人を認識したかをこのAPIでは保持しないと説明している。

限界:

- 一般の実在人物すべてを検出する機能ではない。
- 「有名人に一致しなかった」ことは、「架空人物である」ことを意味しない。
- 有名人データベースの範囲をPina Studio側で完全に確認することはできない。

公式情報:

- https://docs.aws.amazon.com/rekognition/latest/APIReference/API_RecognizeCelebrities.html
- https://docs.aws.amazon.com/rekognition/latest/dg/celebrities.html

## 6. 現時点の候補順位

### 既知CSAM検知

1. Thorn Safer Match
2. Microsoft PhotoDNA

Safer Matchを第一候補とする理由は、API形式が明示され、既知CSAMの暗号学的・知覚ハッシュ照合を目的としているためである。ただし、契約条件を確認するまで採用決定とはしない。

### 新規・未登録CSAMの補助検知

1. Thorn Safer Predictの利用可否を問い合わせる
2. 利用不可の場合は、別の児童安全専門サービスを再調査する

一般的な成人向け画像分類サービスだけをCSAM専用検知の代替にしない。

### 有名人検知

- Amazon Rekognition RecognizeCelebritiesを補助候補とする。
- 有名人不一致を安全証明として使用しない。

### 年齢リスク判定

- Amazon Rekognition DetectFacesの年齢範囲を補助候補とする。
- 18歳以上の本人確認手段として使用しない。
- 判定不能や境界値は拒否する。

## 7. 生成開始前の判定順序

参照画像は、次の考え方に基づいて確認する。

1. 画像は最初に、公開されない非公開の隔離領域へ一時的に受け入れる。この段階では公開URLを発行しない。
2. 隔離領域上の画像1枚ごとに、次の順番で検査する。
   1. URL、MIMEタイプ、容量、画像形式の検証
   2. 既存OpenAI Moderation
   3. 既知CSAMハッシュ照合
   4. 新規・未登録CSAMの補助分類（利用可能な場合）
   5. 顔の有無を検出
   6. 年齢リスク判定
   7. 有名人検知
   8. 実在人物・同意リスクの最終判定
3. 全画像がすべての検査に合格した場合だけ、隔離領域から通常利用用の保存先（`reference-images`等）へ移動またはコピーする。
4. 通常保存先への移動が完了した後にのみ、既存の生成開始処理へ進む。

複数画像のうち1枚でも拒否・障害・判定不能となった場合は、リクエスト全体を停止する。この場合の隔離画像の後片付け条件は§9-1を参照。

## 8. 処理を置く位置

専用検知は、必ず次の処理より前に完了させる。

- `generation_tasks`等のタスク作成
- クレジット残高の控除
- クレジット取引履歴の作成
- OpenRouterへの動画生成リクエスト
- 生成画像・動画の保存

検知で拒否または障害になった場合、クレジットを消費せず、生成タスクを作成せず、OpenRouterへ送信しない。

現在の`generate-prod.html`は、生成開始リクエストより前に`/api/upload-reference-image`を呼び出して画像をアップロードする構成である。そのため、`api/seedance-start-priced.js`側に検知処理を追加するだけでは、生成開始判定より前に画像がすでにStorageへ保存されている状態を防げず不十分である。アップロード処理自体を、非公開の隔離保存を前提として再設計する必要がある。

- 全検査に合格するまで、`reference-images`等の通常保存先へ永続保存しない。
- 全検査に合格するまで、利用者へ公開URLまたは長時間有効な署名付きURLを返さない。

## 9. 安全側停止条件

次の場合はHTTP 503または内容に応じた非成功レスポンスで停止する。

- APIキー未設定
- 契約・利用資格未確認
- 検知サービスのタイムアウト
- HTTPエラー
- 返却JSONの形式不正
- 必須判定項目の欠落
- 画像取得失敗
- 顔はあるが年齢範囲を取得できない
- 年齢範囲の下限が18歳未満
- 年齢範囲が18歳をまたぐ
- 既知CSAM一致
- 新規CSAM分類で危険判定
- 有名人一致
- 実在人物の可能性を安全に否定できない
- 一部画像だけ判定未完了

障害時に「検知できなかったため許可する」という処理は実装しない。

## 9-1. 拒否・障害時の後片付け

次のいずれかに該当した場合、隔離領域の画像を後片付けする。

- 既知CSAM一致
- 新規CSAM危険判定
- 年齢判定不能
- 未成年の可能性
- 有名人一致
- 実在人物リスク
- APIタイムアウト
- HTTPエラー
- JSON形式不正
- 複数画像の一部失敗
- ユーザーによる途中キャンセル

上記に該当した場合は、次を行う。

- 隔離画像を削除する
- 通常保存先へ移動しない
- 公開URLを発行しない
- 削除失敗を一般化した理由コードで記録する
- 削除失敗を放置せず運営者へ通知する

## 10. 実在人物・同意の扱い

技術的な顔検出や有名人検知だけでは、一般人の実在性や本人同意を完全に確認できない。

一般ユーザー向け再開時は、少なくとも次を必要とする。

- 実在人物の画像を無断で使用しないことへの明示同意
- 本人または正当な権利者であることの申告
- 虚偽申告時の利用停止条件
- 通報・異議申立て手順
- 高リスク用途を一律拒否する条件

自己申告だけで安全確認完了とはしない。専用検知と運用手順を組み合わせる。

## 11. ログと保存

隔離領域の画像の扱い:

- 隔離画像の保存期間は必要最小限とする。
- 自動削除期限を設定する。
- 削除処理の成功・失敗を記録する。
- 運営者は危険画像を直接開かない。

ログへ残してよい情報:

- 内部リクエストID
- ユーザーID
- 判定日時
- 使用した検知サービス名
- 成功・拒否・障害の区分
- 一般化した理由コード
- APIのHTTPステータス
- 外部サービスのリクエストID
- 処理時間

通常ログへ残さない情報:

- 画像本体
- 画像のbase64文字列
- 公開URL
- 署名付きURL全文
- プロンプト全文
- 顔の特徴量
- 有名人名
- 年齢推定の詳細値
- CSAMハッシュ値
- APIキー、シークレット
- 外部サービスの生レスポンス全文

児童安全上の証拠保存が必要な場合は、通常のアプリログと分離し、アクセス権限、保存期間、削除禁止条件、法的相談先を決めてから実施する。法的証拠保存が必要な場合は、通常の隔離画像削除処理とは分けて扱い、`docs/operations/CONTENT-REPORT-PROCEDURE.md`と法的助言に従う。

## 12. 通報・自動処理

初期実装では次を自動化しない。

- 警察・NCMEC等への自動通報
- ユーザーアカウントの永久停止
- 証拠画像の自動複製
- 画像の長期保存
- 外部事業者への追加共有

既知CSAM一致等の重大案件は、`docs/operations/CONTENT-REPORT-PROCEDURE.md`と法的助言に従って運営者が対応する。

## 13. 誤判定・異議申立て

- 利用者には危険判定の詳細や検知回避につながる内部しきい値を表示しない。
- 一般化した拒否理由と問い合わせ方法を表示する。
- 異議申立て時も、問い合わせフォームの入力メールだけを本人確認として扱わない。
- 危険画像を運営者が不用意に直接開かない。
- 再判定や解除は、自動ではなく記録を残して行う。

## 14. 導入前に確認する契約事項

各候補サービスについて次を文書で確認する。

- 日本から利用可能か
- 個人事業者または小規模事業者が契約可能か
- 初期費用、月額、従量料金、最低契約額
- 無料試用の有無と条件
- APIの上限、タイムアウト、SLA
- 送信画像の保存有無と保存期間
- サービス改善・学習への利用有無
- データ利用オプトアウト方法
- データ処理地域
- 再委託先
- 契約終了後の削除
- インシデント通知
- 法的報告義務と責任分担
- 誤判定時の問い合わせ先

確認できない項目は「未確認」のまま残し、推測で埋めない。

## 15. テスト方針

文書段階では実APIを呼び出さない。

実装段階では、まず次のモックテストを行う。

- 正常な架空成人キャラクター画像
- 既知CSAM一致を模したレスポンス
- 年齢範囲が18歳未満
- 年齢範囲が18歳をまたぐ
- 年齢判定不能
- 有名人一致
- 顔なし画像
- APIタイムアウト
- HTTP 4xx・5xx
- JSON形式不正
- 複数画像のうち1枚だけ拒否
- 同一リクエストの重複送信
- 検知完了前にクレジット控除・タスク作成・OpenRouter送信が行われないこと
- 検査合格前に公開URLが発行されないこと
- 拒否時に隔離画像が削除されること
- API障害時にも隔離画像が削除されること
- 複数画像の1枚拒否時に全画像が後片付けされること
- 削除失敗が記録・通知されること
- 合格後だけ通常保存先へ移されること

実画像、実CSAM、未成年の性的画像をテスト素材として使用しない。

実API確認が必要になった場合は、事前にユーザーの承認を得て、安全な成人・架空画像だけで最小回数実施する。

## 16. 一般ユーザー向け再開条件

次をすべて満たすまで参照画像生成を一般ユーザーへ再開しない。

- 既知CSAM検知サービスとの契約・利用資格確認
- 新規CSAMへの補助検知方針決定
- 顔・年齢リスク判定方式決定
- 有名人検知方式決定
- 実在人物の同意確認方針決定
- データ保存・オプトアウト設定確認
- 非公開隔離アップロードの実装
- 拒否・障害時の確実な削除
- 公開URLを合格前に発行しないこと
- 削除失敗監視
- Storage権限と保存期間のレビュー
- プライバシーポリシーと利用規約の必要な更新
- 安全側停止を含む実装完了
- モックテスト成功
- セキュリティレビュー完了
- Vercel Preview確認
- 運営者による安全な実API確認
- 本番反映後の動作確認
- 異議申立てと通報対応手順の確認

再開は別PR・別承認とし、この設計文書のマージだけでは停止を解除しない。
