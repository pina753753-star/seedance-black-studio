# アカウント削除依頼の運用手順

Pina Studioでアカウント削除依頼を受けた際に、削除漏れ・誤削除・契約の見落としを防ぐための運営者向け手順です。

この手順は運用確認用です。法令上・取引上・不正防止上の理由で保存が必要な情報や、外部サービス側で直ちに削除できない記録がある場合があります。保存期間や削除可否を確認できない場合は断定せず、各サービスの最新設定・契約・ポリシーを確認します。

## 1. 重要原則

- 本人確認が終わる前に削除しない。
- 対象ユーザーをメールアドレスだけで判断せず、SupabaseのユーザーIDでも照合する。
- Stripeの契約状態と未処理の支払い・返金・異議申し立てを確認する。
- Supabase Authを最初に削除しない。関連データとStorageの確認に必要なユーザーIDを先に記録する。
- DB行の削除だけでStorage、Stripe、Formspree、外部サービスのログ等が消えるとは扱わない。
- 実行結果を記録し、確認できなかった項目を「削除済み」と報告しない。
- 対象、権限、契約状態、保存義務に疑問がある場合は作業を止める。

## 2. 受付

ヘルプセンターのお問い合わせフォームから削除依頼を受け付けます。

受付記録に以下を残します。

- 受付日時
- 依頼者の返信先メールアドレス
- Pina Studioの登録メールアドレス
- 問い合わせ本文
- Formspree上の問い合わせ識別情報
- 対応担当者
- 現在の対応状態

パスワード、カード番号、認証コード、秘密鍵等を問い合わせ本文で送るよう求めません。

## 3. 本人確認

原則として、Pina Studioに登録されているメールアドレスへの返信確認で本人確認を行います。

確認項目:

- 依頼元と登録メールアドレスが一致するか
- Supabase Auth上に対象ユーザーが存在するか
- `profiles`のメールアドレスとユーザーIDが一致するか
- なりすまし、不正利用、第三者による申請の疑いがないか

登録メールアドレスを利用できない申告がある場合は、その場で削除せず、追加確認方法を個別に判断します。十分な本人確認ができない場合は作業を停止します。

本人確認のために、生年月日の全文、パスワード、カード情報等の過剰な情報を求めません。

## 4. 作業前記録

削除作業前に、次の識別情報と状態を運営記録へ残します。

- Supabase AuthのユーザーID
- 登録メールアドレス
- `profiles`の表示名・権限・プラン
- Stripe顧客ID
- Stripe契約IDと契約状態
- クレジット残高
- 生成・編集タスクの件数
- Storage上の対象ファイルの件数または確認結果
- 未処理の問い合わせ、返金、障害対応の有無

機密情報、プロンプト本文、画像・動画そのものを、必要性なく運営記録へ複製しません。

## 5. 削除を保留する条件

次に該当する場合は、削除範囲と保存要否を確認するまで作業を止めます。

- 本人確認が完了していない
- 対象ユーザーIDを一意に特定できない
- 有効なサブスクリプションがある
- 未確定の支払い、返金、チャージバック、異議申し立てがある
- 未完了の動画生成・編集タスクがある
- 不正利用、セキュリティ事故、児童安全、法令対応に関する調査中である
- 取引・会計・監査記録として保存が必要な可能性がある
- 削除対象が別ユーザーのデータと混在している
- 外部サービスの状態を確認できない

## 6. Stripeの確認

Stripeダッシュボードで、記録したStripe顧客IDを使用して確認します。

確認項目:

- 有効または解約予約中のサブスクリプション
- 未払い・処理中の請求
- 返金
- チャージバック・異議申し立て
- 今後の請求予定

有効なサブスクリプションがある場合は、依頼者の意思と現在の契約状態を確認してから解約します。解約とアカウント削除を同一操作として扱いません。

カード番号等はStripeが管理します。Pina Studio側でカード情報を取得・保存・削除しません。

取引記録は法令やStripeの保持方針により残る場合があるため、削除できない記録を「完全削除済み」と案内しません。

## 7. Supabase Storageの確認と削除

Supabase Authを削除する前に、ユーザーID、DB上の保存パス、URL等を基に対象ファイルを特定します。

確認対象:

- 参照画像
- 生成動画
- ウォーターマーク済み動画
- 編集動画
- その他ユーザー固有のアップロードファイル

確認事項:

- `reference-images`等の対象バケット
- ユーザーIDを含む保存パス
- 生成・編集タスクに記録された保存先
- 公開サンプルに設定された動画の有無

削除前に、対象ファイルが申請者本人のものかを確認します。共有ファイルや別ユーザーのデータを削除しません。

公開サンプルの場合は、公開解除と元ファイル削除の両方を確認します。

削除したファイルのバケット名、パス、件数、実行日時、結果を記録します。URLへアクセスできないことだけを、Storageから完全に削除された証拠とは扱いません。

## 8. Supabase Databaseの確認と削除

ユーザーIDを基準に、次の関連データを確認します。

- `profiles`
- `private.user_age_verifications`
- `credit_balances`
- `credit_transactions`
- `user_subscriptions`等の契約関連行
- `annual_credit_grant_log`
- 生成タスク・動画履歴関連行
- `video_edit_tasks`
- その他ユーザーIDに紐づく行

削除順序は、外部契約・Storage・監査上必要な確認を終えた後に決めます。

外部キーによる連動削除が定義されていても、実際の対象と削除結果を確認します。連動削除を推測だけで完了扱いにしません。

取引、返金、不正防止、障害調査等のため保存が必要な行は、削除可否と保存根拠を確認します。必要に応じて個人を直接識別する情報の分離・匿名化を検討しますが、手順や法的要件を確認せず独断で実施しません。

## 9. Supabase Authの削除

次をすべて確認した後、Supabase Authの対象ユーザーを削除します。

- 本人確認完了
- Stripe確認完了
- 未完了タスクなし、または対応方針確定
- Storage確認完了
- DB関連行の確認完了
- 保存が必要な記録の扱い確定
- 対象ユーザーIDの再照合完了

削除後に確認する項目:

- Supabase Auth上に対象ユーザーが存在しない
- ログインできない状態になっている
- 連動削除対象の行が想定どおり処理された
- 残す必要がない個人データがDBに残っていない

本番でログイン試験やパスワード操作を行う必要がある場合は、事前にユーザーの承認を得ます。

## 10. Formspree・外部サービス・ログの確認

次のサービスについて、削除依頼に関連するデータの有無と、削除可否・保持条件を確認します。

- Formspree
- Vercel
- Railway
- OpenAI
- OpenRouter
- Anthropic等の利用モデル提供者
- Supabaseのログ・バックアップ
- Stripe

確認対象には、問い合わせ、アクセスログ、エラーログ、監査ログ、IPアドレス、ブラウザ情報、一時ファイル等が含まれる場合があります。

リポジトリから外部サービス側の保持期間や個別削除可否を確認できない場合は、各サービスの最新設定・契約・ポリシーを確認します。

通常の管理画面から個別削除できないログやバックアップがある場合は、その事実、保持理由、想定される保持範囲を記録します。確認できないものを削除済みとしません。

## 11. 利用者端末に残るデータの案内

利用者のブラウザにCookie、認証セッション、localStorage内の設定・プロンプト下書き等が残る場合があります。

完了連絡では、必要に応じて次を案内します。

- Pina Studioからログアウトする
- ブラウザの`pinastudio.jp`のCookie・サイトデータを削除する
- 複数端末を利用している場合は端末ごとに削除する
- 保存済み・ダウンロード済みの画像や動画は利用者自身で削除する

運営側で利用者端末のデータを遠隔削除できるとは案内しません。

## 12. 完了確認

次のチェックがすべて完了したか確認します。

- [ ] 受付記録を作成した
- [ ] 本人確認が完了した
- [ ] SupabaseユーザーIDを記録した
- [ ] Stripeの契約・支払い・返金状況を確認した
- [ ] 未完了の生成・編集タスクがないことを確認した
- [ ] Supabase Storageの対象を確認した
- [ ] 削除対象ファイルを削除し結果を記録した
- [ ] DB関連行を確認した
- [ ] 保存が必要な取引・監査記録の扱いを確認した
- [ ] Supabase Authを削除した
- [ ] Auth削除後の関連行を確認した
- [ ] Formspreeの問い合わせ記録を確認した
- [ ] 外部サービスのログ・一時ファイル・バックアップを確認した
- [ ] 確認できなかった項目を記録した
- [ ] 利用者端末に残るデータの削除方法を案内した
- [ ] 完了連絡を送信した

## 13. 利用者への完了連絡

完了連絡には次を含めます。

- アカウント削除手続きの完了日
- Pina Studioへログインできなくなったこと
- サブスクリプションの解約状態
- Pina Studioが直接管理する削除対象データの対応結果
- 法令、取引、監査、不正防止、外部サービスの仕様等により残る場合がある記録
- 利用者端末のCookie・サイトデータ・ダウンロード済みファイルの削除方法
- 問い合わせ先

削除を確認できていない保存先について、「すべて完全に消去しました」と断定しません。

## 15. 定期見直し

次の場合に本手順と`DATA-INVENTORY.md`、`privacy.html`を見直します。

- 新しい外部サービス、AIモデル、DBテーブル、Storageバケットを追加したとき
- アカウント削除機能を実装したとき
- Stripeの契約・解約フローを変更したとき
- 保存期間や削除方針を決めたとき
- 法令、契約、外部サービスの仕様が変わったとき
- 実際の削除依頼で手順漏れが見つかったとき
